## 1. Executive Summary & Purpose

Loomwright is a native Windows desktop shell written in Rust (`tao` + `wry` + WebView2) hosting an embedded web writing desk.

This session addressed two core requests:
1. **Clean-Slate First Run (v1.6.0.0):** Eliminate dummy/demo fiction projects (e.g., `"The Glass Orchard"` under ID `"p-demo"`) from new installations, bump the application and installer version to `1.6.0.0`, and ensure users always start with an empty library.
2. **Installers (.exe & .msi) on GitHub:** Automate building and publishing Windows installers (`.exe` and `.msi`) so users can download and install the app directly from GitHub.

---

## 2. Completed Work: Clean-Slate & v1.6.0.0 Update

All requirements for the clean-slate data model and version bump are **fully implemented, tested, committed, and pushed**:

### A. Data Sanitization & Runtime Guard (`loomwright-window/src/server.rs`)
* **Fresh Install:** When `%APPDATA%\Loomwright\shared.json` does not exist on startup, the server writes an explicit empty snapshot (`revision: 0, record: null`) before binding the TCP listener. The web layer recognizes `null` and initializes an empty project library.
* **Upgrade Guard:** Added `purge_demo_data(mut record: serde_json::Value)` to detect and strip any project containing the legacy demo sentinel ID (`"p-demo"`). If all remaining projects are demo data, it resets the record so the user begins with a clean slate.
* **Revision Counter:** Persisted immediately on first launch to maintain stable optimistic concurrency on `/api/sync`.

### B. Version Bump to `1.6.0.0`
* `loomwright-window/web/app.js`: Updated `const APP_VERSION = '1.6.0.0';`.
* `loomwright-window/Cargo.toml`: Updated package version to `1.6.0`.
* `loomwright-window/build.rs`: Updated `FileVersion` and `ProductVersion` embedded Windows resource strings to `1.6.0.0`.
* `installer/loomwright.nsi`: Default version defined as `1.6.0` with `VIProductVersion "1.6.0.0"`.
* `installer/README.txt` & `README.md`: Updated getting-started copy to state that new installations start with an empty canvas.

### C. Installer Cleanup Routine (`installer/loomwright.nsi`)
* In `SecMain`, the installer deletes legacy `%APPDATA%\Loomwright\shared.json` and `%APPDATA%\Loomwright\shared.json.bak`.
* User manuscripts stored in the WebView2 profile (`%LOCALAPPDATA%\Loomwright\WebView2`) are **strictly preserved**.

## 5. Instructions for the Next AI / Developer

To complete the setup and make both download links work cleanly:

### Task A: Fix the `.msi` Build in GitHub Actions (`.github/workflows/release.yml`)
The runner image on GitHub Actions (`windows-latest` / Windows Server 2025) has deprecated WiX v3 in favor of WiX v4+ via .NET global tools. 

**Recommended fix:** Replace the WiX setup step in `.github/workflows/release.yml` with modern WiX v4:
```yaml
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.x'

      - name: Install WiX CLI
        run: dotnet tool install --global wix

      - name: Build WiX MSI Installer
        shell: pwsh
        run: |
          cd installer
          wix build loomwright.wxs -o Loomwright-Setup-1.6.0.msi
```
*Note:* If using WiX v4, convert `installer/loomwright.wxs` namespace to `<Wix xmlns="http://wixtoolset.org/schemas/v4/wxs">`.

### Task B: Immediate Fallback Option for `.msi`
If an `.msi` is not strictly required by an enterprise software deployment policy, update `README.md` to feature the working `Loomwright-Setup-1.6.0.exe` installer as the primary download, with the releases page URL:
* `https://github.com/soloanalysis28-dev/loomwright-desktop/releases/latest`
* Direct EXE: `https://github.com/soloanalysis28-dev/loomwright-desktop/releases/download/v1.6.0/Loomwright-Setup-1.6.0.exe`

### Task C: (Optional) Commit `Loomwright-Setup-1.6.0.exe` to Repo
The installer binary is already present locally at `installer/Loomwright-Setup-1.6.0.exe` (3.15 MB, well below GitHub's 50 MB limit). Committing this file directly to the repository under `installer/` guarantees that users who download the repo ZIP will always find the executable ready to run immediately.
